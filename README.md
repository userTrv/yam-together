# Вагон

Общая очередь, где у всех в наушниках играет один трек секунда в секунду. Каждый слушает со своего телефона и через свой аккаунт Яндекс Музыки. Сделан для метро: при пропадании связи музыка не останавливается.

- Создать вагон → получить код из 5 знаков и QR → друзья заходят по ссылке.
- Каждый добавляет треки, очередь выглядит как ветка метро: станция = трек, цвет участка = кто добавил.
- Пауза, перемотка, «дальше» общие. Хозяин может забрать пульт, тогда остальные пропускают трек голосованием.
- Реакции, статус синхронизации каждого пассажира, сдвиг под задержку Bluetooth-наушников.
- Демо-треки синтезируются прямо в браузере: работает без аккаунта и без сети.

## Запуск

Нужен Node.js 22+. Зависимостей нет.

```bash
npm start                 # http://127.0.0.1:8787
npm test                  # юнит-тесты: таймлайн, комнаты, сервер, прокси Яндекса (на моке)
npm run test:e2e          # 3 браузера в одном вагоне, меряет разброс звука (нужен Playwright и запущенный сервер)
```

Переменные окружения: `PORT` (8787), `HOST` (127.0.0.1), `TRUST_PROXY=1` за обратным прокси, `YM_API_BASE` для тестов.

## Как это работает коротко

Сервер не стримит звук. Он хранит очередь и «якорь»: какой трек и в какой момент серверного времени у него была нулевая секунда. Телефоны сверяют часы с сервером (как NTP) и сами вычисляют, где сейчас должен быть трек, по общему файлу [shared/timeline.js](shared/timeline.js). Плеер каждые 250 мс сравнивает свою позицию с расчётной: мелкое расхождение лечит скоростью ±6%, крупное перемоткой. Текущий и следующий треки скачиваются целиком заранее.

В e2e-тесте на одной машине три вкладки после трёх секунд держат разброс 3–4 мс. Между разными телефонами добавляется погрешность сверки часов (обычно 5–30 мс на мобильной сети) и задержка наушников.

## Яндекс Музыка

Официального API для сторонних приложений у Яндекс Музыки нет. Прототип использует те же эндпоинты, что мобильный клиент, по описанию open-source библиотеки [MarshalX/yandex-music-api](https://github.com/MarshalX/yandex-music-api): поиск, `download-info` и подписанную ссылку на mp3. Каждый пассажир подключает свой аккаунт, токен живёт только в его браузере, сервер его не хранит и не логирует.

Это годится для прототипа и демо, но не для публичного запуска: для продукта нужен договор с Яндексом или запуск внутри Яндекс Музыки. Подробности в [docs/pitch-yandex.md](docs/pitch-yandex.md).

Сервер должен стоять в России: из других стран API отвечает `451 Unavailable For Legal Reasons`.

## Деплой

Один процесс Node за Caddy или nginx: [deploy/Caddyfile.example](deploy/Caddyfile.example) и юнит [deploy/vagon.service](deploy/vagon.service) (отдельный пользователь, `ProtectSystem=strict`, `TRUST_PROXY=1`). Для nginx важно `proxy_buffering off` на `/api/rooms/`, иначе события SSE будут приходить пачками. Состояние вагонов в памяти: при перезапуске вагоны пропадают, клиенты предложат войти заново.

## Структура

```
server/index.js     HTTP, статика, API вагонов, SSE, лимиты
server/rooms.js     логика вагона: участники, очередь, пульт, голосование
server/yandex.js    прокси к API Яндекс Музыки
shared/timeline.js  общий расчёт «что играет сейчас», работает и в Node, и в браузере
public/js/player.js синхронный плеер
public/js/clock.js  сверка часов
public/js/synth.js  синтез демо-треков
public/js/qr.js     генератор QR без зависимостей
```
